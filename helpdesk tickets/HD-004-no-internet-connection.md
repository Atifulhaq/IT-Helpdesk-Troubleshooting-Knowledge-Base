# Practice Helpdesk Ticket 004: No Internet Connection

## Ticket Information
- Ticket ID: HD-004
- Category: Network / Connectivity
- Priority: Medium (provisional)
- Status: Practice scenario
- Reported by: Example user
- Device: Windows computer

## Reported Issue
The user reports that their computer cannot access the internet, preventing them from using websites and online services.

## Initial Assessment
The cause is unknown. Possible causes include a Wi-Fi connection problem, a router issue, an incorrect network configuration or a wider service outage.

## Troubleshooting Steps
1. Ask when the problem started and whether other users are affected.
2. Check whether Wi-Fi or Ethernet is connected.
3. Ask whether other devices can access the internet.
4. Test more than one website to determine whether the issue is website-specific.
5. Record any error messages displayed.
6. If permitted, disconnect and reconnect to the network.
7. Follow organisational procedures for any further network checks.
8. Record the findings and escalate if the problem continues.

## Simulated Resolution
For this practice scenario, assume the computer had disconnected from Wi-Fi. After reconnecting to the correct network, internet access was restored and tested.

Note: This is an illustrative scenario, not a real incident or verified test result.

## User Confirmation
In a real ticket, ask the user to confirm that the required websites or services work before closing the ticket.

## Escalation
Escalate if:
- Multiple users or devices are affected.
- The connection remains unavailable after approved initial checks.
- Network infrastructure or administrator access may be required.
- There are signs of a wider service outage.

## Security and Professional Practice
- Only perform authorised troubleshooting actions.
- Do not change network settings without permission.
- Record findings clearly without including sensitive credentials.

## Lessons Learned
- Establish the scope of the problem before troubleshooting.
- Check basic connectivity before assuming a complex network fault.
- Record actions and results.
- Confirm the outcome before closing a real ticket.
